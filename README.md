# Continuum 1.0 — капсулы преемственности

Веб-приложение создаёт переносимый пакет файлов с цифровой подписью и повторяемыми критериями приёмки. Предназначено для передачи данных, описаний и условий между владельцами рабочего процесса.

Публичный адрес: https://continuum-capsule-vault.calmtapir1.chatgpt.site

Доступ по ссылке без входа в ChatGPT. Доступ к опубликованному инструменту не означает передачу прав администрирования этого Site другому аккаунту.

## Что реализовано

- Создание пакетов до 32 файлов / 5 МиБ, SHA-256 и подпись ECDSA P-256 / SHA-256.
- Проверка точного состава и байтов файлов, сравнение JSON-поля, проверка колонок и структуры CSV.
- Сверка fingerprint по независимому доверенному каналу.
- Экспорт обычного или зашифрованного пакета: AES-256-GCM, PBKDF2-SHA256, 210 000 итераций.
- Явное сохранение в IndexedDB, повторное открытие, экспорт, удаление локальной копии.
- Автономный однофайловый HTML-проверяющий и независимый CLI-проверяющий.
- Отсутствуют внешние библиотеки, CDN-скрипты, платёжные системы и аналитика.

Сайт использует статическую публикацию через HTTPS; данные обрабатываются в браузере. Сервер не нужен для выпуска и проверки капсул. `dist/` — полный результат сборки, `tests/` — автоматическая проверка, `docs/` — модель и ограничения, Конфигурация с идентификатором исходного Site исключена: для независимого развёртывания используйте свой хостинг. Сайт не сохраняет файлы в облаке. Аккаунты, продажи, блокчейн и рынок токенов не реализованы.

## Запуск и проверка исходников

Нужен Node.js 20+ (проверено на 24). Установка зависимостей не требуется.

```bash
npm test
node scripts/build-offline.mjs
```

Для локального просмотра нужен HTTP-сервер. Например, при установленном Python из корня проекта:

```bash
python3 -m http.server 8080 --directory dist --bind 127.0.0.1
```

Откройте `http://localhost:8080`. Это сервер для локального просмотра, не рекомендация для публичного production. Для промышленного размещения отдавайте `dist/` через HTTPS/CDN со стандартной защитой HTTP и текущим кодом. Используйте отдельный домен и origin, не размещайте приложение рядом с недоверенными скриптами. Статическое приложение не исполняет содержимое файлов.

Автономная проверка: скачайте `dist/offline-verifier.html` из доверенного источника и откройте в современном браузере. Доступность WebCrypto для `file://` зависит от браузера и его политики. При запрете используйте localhost или CLI. Воспроизведение подтверждённого результата производится движком, а не доверием к текстовому отчёту.

Независимый CLI:

```bash
node scripts/verify.mjs capsule.continuum.json --fingerprint <64-символьный SHA256>
node scripts/verify.mjs encrypted.continuum.json --password-stdin
```

Во втором случае введите пароль через stdin; не включайте пароль в аргументы командной строки, журнал команд или исходники. Коды CLI: 0 — все проверки прошли; 1 — пакет не прошёл проверку; 2 — ошибка ввода или расшифрования. Без fingerprint не проверяется доверие к автору.

## Границы доверия

Ключ подписи создаётся отдельно для каждой капсулы, остаётся в памяти во время создания и не экспортируется. Сохраняется только публичный ключ. Это не долговременная идентичность. Любой может создать другой пакет и указать любое имя. Получателю необходимо отдельно получить fingerprint и проверить фактические права и личность.

Цифровая подпись не удостоверяет время, права, достоверность, отсутствие вредоносных данных или ценность. Критерии JSON/CSV проверяют только заявленные свойства, а не фактическое восстановление полного приложения, инфраструктуры или бизнеса. Не запускайте полученные исполняемые файлы без отдельной проверки.

Локальная база IndexedDB не зашифрована и может исчезнуть при очистке данных браузера. Скачивайте резервные копии. Пароль экспорта не хранится и не восстанавливается. Слабый пароль или заражённое устройство снижают защиту. Независимого внешнего аудита безопасности пока нет.

## Выпуск и эксплуатация

1. Запустите все тесты и пересоберите автономный проверяющий после изменения движка или шифрования.
2. Проверьте создание, импорт, pin, отрицательную проверку, экспорт с паролем и локальное хранение в целевых браузерах.
3. Разместите точную проверенную версию `dist/` по HTTPS. Не подключайте внешние скрипты или пользовательский HTML.
4. После изменения формата сохраняйте обратную совместимость или увеличивайте его версию. Не переписывайте алгоритмы без криптографической экспертизы.
5. Проверяйте доступность URL и выполняйте тестовый цикл на синтетических файлах после выпуска. Мониторинг 24/7 не настроен.
6. Предыдущую сохранённую версию можно повторно опубликовать через Sites. Локальные капсулы не мигрируют между доменами автоматически.

Это работающий продукт ограниченной функции, а не доказанное изобретение первого в мире типа актива. Часть технических принципов существует в BagIt, RO-Crate и in-toto. Спрос, стоимость и выручка не установлены. Подробности — в `docs/PRIOR_ART.md` и `docs/BUSINESS.md`.
